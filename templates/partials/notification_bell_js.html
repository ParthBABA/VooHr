{# openNotification: shared by dashboard, conversation-workspace and risk-drift. These three carried the same handler; risk-drift's copy was missing only the explanatory comment, which this partial restores. Behaviour is unchanged: the bell clears the row's unread dot and decrements the badge immediately (optimistic), then marks the notification read and only navigates once that request has been sent — markRead(...).then(navigate), never navigate-first, because navigating immediately cancels the request and the red badge comes back. Meeting-family notifications route to the meeting tracker for the related employee, and everything else falls through to the shared window.VooNotif.targetUrl(). ── Seen-while-open ──────────────────────────────────────────────────── The red dot outlived the reading. Opening the bell marked nothing, so rows the user had plainly looked at stayed unread until they were clicked — and the dot is worse than that, because it tracks the org-wide unread_count while the panel only ever lists the newest 5. Reading those 5 left the older ones behind them with nothing on screen to clear them. So the bell now marks what was actually read. Every unread row gets a ~1s dwell timer armed by an IntersectionObserver rooted at #notifList (the panel's own scroll box, threshold 0.6), so a row merely scrolled past — or one still hidden behind a closed dropdown, which is display:none and therefore never intersects — does not count. The ids are batched into a single VooNotif.markManyRead() call, and a successful batch re-reads the endpoint: the panel holds 5 rows and the badge holds every unread row in the org, so the server's unread_count is the only number worth believing and the local decrement is only there to make the UI feel instant. A failed batch puts the rows and the count back rather than leave the page claiming something the server never agreed to. These functions sit in the including page's closure on purpose: updateBadge, renderList and loadNotifications are page-local, so the badge, the panel and the request all move together.
